# 강아지 산책 메이트 웹 포트폴리오 기획서

## 1. 프로젝트 개요

`강아지 산책 메이트`는 동네 기반으로 강아지 산책 메이트를 찾고, 실제 산책 약속까지 연결하는 서비스다.

이 문서는 현재 프로젝트 내부 문서를 복사해서 쓰는 용도가 아니라, `다른 디렉토리에서 새롭게 웹 포트폴리오 프로젝트를 만들 때 바로 사용할 수 있는 독립형 기획서`를 목표로 한다.

이 서비스의 핵심은 단순한 반려견 커뮤니티가 아니라 `근처 사람을 발견하고, 신뢰를 판단하고, 실제 산책 약속으로 이어지는 흐름`이다.

---

## 2. 서비스 정의

### 핵심 아이디어

- 같은 생활권의 반려견 보호자가 주변 산책 메이트를 찾는다
- 대화를 시작하기 전에 신뢰와 궁합을 빠르게 판단할 수 있어야 한다
- 온라인 탐색이 오프라인 산책 약속으로 자연스럽게 이어져야 한다

### 핵심 사용자 흐름

1. 사용자가 지도에서 근처 산책 메이트를 본다
2. 프로필, 강아지 정보, 거리, 최근 활동, 매너온도를 확인한다
3. 산책 요청을 보낸다
4. 채팅에서 약속을 조율한다
5. 피드에서 산책 기록과 분위기를 확인하거나 공유한다
6. 마이페이지에서 자신의 활동과 신뢰도를 관리한다

### 서비스 성격

- 동네 중심
- 실용적
- 따뜻함
- 신뢰 중심
- 생활형 서비스
- 커뮤니티는 보조, 매칭은 핵심

---

## 3. 포트폴리오 목표

이 프로젝트는 단순히 예쁜 화면을 만드는 것이 아니라, 아래 역량을 보여주는 포트폴리오여야 한다.

- 서비스 기획 능력
- 정보 구조 설계 능력
- 반응형 웹 제품 설계 능력
- 재사용 가능한 컴포넌트 설계 능력
- 디자인 시스템 정리 능력
- 실제 서비스처럼 보이는 제품 감각

결과물은 `모바일 앱 시안을 웹에 억지로 늘린 화면`이 아니라, `웹에서도 충분히 설득력 있는 반응형 서비스`처럼 보여야 한다.

### 주요 사용자

- 20~40대 반려견 보호자
- 강아지 산책을 자주 하는 사용자
- 혼자보다 근처 메이트와 함께 산책하고 싶은 사용자
- 만나기 전 신뢰와 궁합을 빠르게 확인하고 싶은 사용자

### 사용자 니즈

- 지금 근처에 누가 있는지 알고 싶다
- 믿을 만한 사람인지 빠르게 판단하고 싶다
- 우리 강아지와 잘 맞을지 보고 싶다
- 빠르게 산책 약속을 잡고 싶다

## 6. 핵심 UX 원칙

### 원칙 1. 지도는 서비스의 중심이다

가장 중요한 화면은 지도다.

사용자는 3초 안에 아래를 이해할 수 있어야 한다.

- 근처에 누가 있는지
- 누가 신뢰할 만한지
- 누구에게 바로 요청할 수 있는지

### 원칙 2. 대화보다 먼저 신뢰 판단이 가능해야 한다

사용자는 여러 화면을 깊게 들어가지 않아도 매칭 가능성을 판단할 수 있어야 한다.

초기에 잘 보여야 하는 정보는 다음과 같다.

- 거리
- 최근 활동 시간
- 강아지 이름 / 견종 / 크기
- 산책 스타일
- 선호 시간대
- 매너온도

### 원칙 3. 웹 우선으로 설계한다

이 프로젝트는 앱보다 `웹 포트폴리오`가 우선이다.

- 데스크탑에서는 분할 레이아웃을 적극 활용한다
- 태블릿에서는 비교와 탐색의 균형을 잡는다
- 모바일에서는 같은 정보 우선순위를 유지한 채 빠른 행동이 가능해야 한다

### 원칙 4. 커뮤니티는 매칭을 보조해야 한다

피드와 마이페이지는 메인 기능이 아니라 보조 기능이다.

이 화면들은 다음 역할을 해야 한다.

- 실제 활동감 제공
- 사용자 분위기 전달
- 신뢰 강화
- 관계 유지

## 7. 정보 구조

### 주요 경로

- `/login`
- `/signup`
- `/map`
- `/feed`
- `/chat`
- `/chat/[roomId]`
- `/mypage`

### 경로별 역할

- `Map`: 탐색, 비교, 선택, 요청
- `Feed`: 동네 활동, 산책 이야기, 서비스 분위기
- `Chat`: 약속 조율, 대화, 관계 유지
- `MyPage`: 프로필, 신뢰도, 활동 관리
- `Auth`: 진입, 가입, 강아지 정보 수집

### 우선순위

1. Map
2. Chat
3. Feed
4. MyPage
5. Auth

## 8. 화면 기획

### 8-1. Map

이 프로젝트의 대표 화면이다.

#### 필수 구조

- 데스크탑: `리스트 + 지도` 분할 구조
- 모바일: `리스트/지도 전환` 구조
- 필터 영역: 견종 크기, 산책 스타일, 선호 시간대
- 신뢰 판단이 가능한 사용자 카드
- 선택된 메이트의 상세 패널 또는 바텀시트
- 명확한 산책 요청 CTA

#### 반드시 보여야 하는 정보

- 사용자 이름
- 강아지 이름
- 견종
- 강아지 크기
- 산책 스타일
- 선호 시간
- 거리
- 최근 활동
- 매너온도

#### UX 목표

비교가 쉽고, 요청 전환이 빠른 탐색 화면이어야 한다.

### 8-2. Feed

피드는 일반 SNS가 아니라 `동네 산책 활동의 분위기와 실제성`을 보여주는 허브여야 한다.

#### 필수 구조

- 게시물 리스트
- 생활감 있는 콘텐츠 구성
- 데스크탑에서는 보조 위젯 또는 사이드 정보 영역 가능

#### 콘텐츠 성격

- 산책 후기
- 짧은 일상 기록
- 동네 분위기
- 강아지 관련 활동

#### UX 목표

사용자가 이 서비스에 실제 활동이 있고, 진짜 사람들이 이용하는 느낌을 받아야 한다.

### 8-3. Chat

채팅은 일반 메신저라기보다 `산책 약속 조율 도구`에 가깝다.

#### 필수 구조

- 데스크탑: 채팅 목록 + 대화창 분할 레이아웃
- 모바일: 채팅 목록과 채팅방 라우트 분리
- 상단에 상대 정보와 관계 맥락이 가볍게 드러나면 좋다

#### UX 목표

사용자가 즉시 아래를 이해해야 한다.

- 누구와 대화 중인지
- 왜 대화 중인지
- 다음 행동이 무엇인지

### 8-4. MyPage

마이페이지는 자기 표현보다 `신뢰와 활동 관리`가 중심이어야 한다.

#### 필수 구조

- 프로필 요약
- 강아지 요약 정보
- 매너온도 영역
- 활동 통계
- 최근 산책 기록 또는 받은 칭찬
- 관리 메뉴

#### UX 목표

사용자가 자신이 다른 사람에게 어떻게 보이는지 바로 이해할 수 있어야 한다.

### 8-5. Auth

인증 화면은 가볍고 친절해야 하며, 진입장벽이 낮아 보여야 한다.

#### 필수 구조

- 로그인
- 회원가입
- 강아지 정보 입력 단계

#### UX 목표

복잡한 온보딩이 아니라, 바로 시작할 수 있는 서비스처럼 느껴져야 한다.

## 11. 반응형 전략

### 모바일

- 빠른 탐색
- 강한 1차 행동 유도
- 단일 컬럼 구조
- 하단 네비게이션

### 태블릿

- 카드 밀도 확대
- 탐색과 비교의 균형
- 스택형과 분할형의 자연스러운 전환

### 데스크탑

- 분할 레이아웃을 핵심 패턴으로 사용
- 목록, 지도, 상세 패널의 동시 활용
- 관리와 비교에 적합한 레이아웃

데스크탑은 단순 확대판이 아니라, 웹다운 구조여야 한다.

## 12. 기술 스택

이 포트폴리오 프로젝트는 아래 기술 스택을 기준으로 한다.

- Next.js 16.1.6
- React 19.2.3
- TypeScript
- App Router
- Tailwind CSS v4
- lucide-react
- next/font/google

### 구현 제약

- 외부 UI 프레임워크를 전제로 하지 않는다
- Tailwind 유틸리티와 CSS 변수로 구현 가능한 구조여야 한다
- 지나치게 복잡한 캔버스형 인터랙션은 피한다
- 현실적인 웹 제품 패턴을 우선한다
- 초기에는 Mock 데이터 기반으로 구현한다

### 권장 구현 방향

- 공통 레이아웃 셸
- 라우트 기반 페이지 구조
- feature 단위 컴포넌트 그룹핑
- 재사용 가능한 UI 프리미티브
- 글로벌 CSS 토큰 정리

## 15. 성공 기준

## 16. 최종 한 줄 정의

`강아지 산책 메이트`는 지도와 신뢰 정보를 중심으로, 동네 반려견 보호자들이 실제 산책 약속까지 이어질 수 있도록 설계된 반응형 웹 포트폴리오 서비스다.
