# 현재 프론트 분석 기반 리디자인 브리프

## 1. 이 문서의 목적

이 문서는 `현재 디렉토리의 프론트 작업물`을 분석해,

- 이 프로젝트가 어떤 프로그램인지 정리하고
- 어떤 기능과 흐름을 핵심으로 보고 있는지 해석하고
- 다른 디렉토리에서 `같은 메인 테마를 유지한 채 다른 디자인으로 새 프론트`를 만들 수 있도록
- 리디자인 기준 문서로 쓰기 위해 작성한다

즉, 이 문서는 새로운 프로젝트를 위한 `분석 기반 리디자인 기획서`다.

---

## 2. 현재 프로젝트가 어떤 프로그램인가

현재 프론트는 `동네 기반 강아지 산책 메이트 매칭 서비스`다.

이 서비스는 단순한 반려견 커뮤니티나 사진 공유 앱이 아니라,

- 근처 사용자 탐색
- 강아지 정보와 사용자 신뢰 정보 확인
- 산책 요청
- 채팅을 통한 약속 조율
- 피드와 마이페이지를 통한 활동 유지

로 이어지는 `실제 산책 연결형 서비스`로 해석된다.

한 줄로 정리하면:

`근처 반려견 보호자끼리 산책 메이트를 찾고, 신뢰를 확인한 뒤 실제 산책 약속까지 이어주는 서비스`

---

## 3. 현재 프로젝트의 핵심 구조 해석

현재 화면 구조를 보면 서비스의 중심은 분명히 `Map`이다.

### 핵심 흐름

1. 지도에서 주변 메이트를 본다
2. 프로필과 강아지 정보를 본다
3. 거리, 최근 활동, 산책 스타일, 선호 시간, 매너온도를 확인한다
4. 산책 요청을 보낸다
5. 채팅에서 약속을 잡는다
6. 피드에서 활동을 보거나 공유한다
7. 마이페이지에서 신뢰도와 활동을 관리한다

즉, 현재 프로젝트는 `지도 탐색 -> 매칭 -> 채팅`이 주 흐름이고,
`피드 / 마이페이지`는 관계 유지와 신뢰 보강용 보조 흐름이다.

---

## 4. 현재 프론트에서 확인되는 주요 화면 역할

### 4-1. Map

현재 프로젝트의 메인 화면이다.

역할:

- 주변 사용자 탐색
- 메이트 비교
- 필터링
- 상세 정보 확인
- 산책 요청

현재 구현은 모바일에서 리스트/지도 전환, 데스크탑에서 분할 구조를 의도하고 있다.

### 4-2. Feed

보조 커뮤니티 화면이다.

역할:

- 산책 후기
- 동네 분위기 확인
- 실제 사용자 활동감 전달

즉, 매칭 서비스의 신뢰도를 높이는 생활형 콘텐츠 허브다.

### 4-3. Chat

일반 메신저보다 `산책 약속 조율`에 가까운 화면이다.

역할:

- 요청 이후 대화 지속
- 약속 시간 조율
- 관계 유지

### 4-4. MyPage

자기 표현보다 `신뢰도 관리`에 가깝다.

역할:

- 프로필 및 강아지 정보 관리
- 매너온도 확인
- 활동량 확인
- 산책 기록 또는 칭찬 관리

### 4-5. Auth

서비스 입구 역할이다.

역할:

- 회원가입
- 로그인
- 강아지 정보 입력 시작

## 5. 현재 프로젝트에서 중요한 정보 요소

이 서비스는 시각적으로 예쁜 것보다, 사용자가 `만나도 되는 사람인지` 빠르게 판단할 수 있어야 한다.

그래서 아래 정보는 어떤 새 디자인에서도 유지되어야 한다.

- 사용자 이름
- 강아지 이름
- 견종
- 강아지 크기
- 산책 스타일
- 선호 시간대
- 거리
- 최근 활동 시간
- 매너온도
- 총 산책 횟수 또는 활동량

이 정보들은 이 서비스의 핵심 판단 기준이다.

## 6. 현재 디자인의 특징

현재 프론트의 비주얼 방향은 아래처럼 읽힌다.

- 오프화이트 기반 배경
- 앰버 / 오렌지 포인트 컬러
- 부드러운 회색 톤
- 둥근 카드와 입력창
- 생활형 서비스 느낌
- 데스크탑에서는 글래스모피즘 기반 셸 구조
- 모바일에서는 앱형 하단 네비게이션 구조

현재 분위기를 한 줄로 정리하면:

`따뜻하고 친근한 반려견 라이프스타일 앱`

---

## 7. 현재 디자인의 장점

- 서비스 주제가 바로 읽힌다
- 오렌지 계열 컬러가 따뜻한 느낌을 준다
- 카드 중심 구조라 정보 파악이 쉽다
- 지도, 피드, 채팅, 마이페이지 역할이 비교적 분명하다
- 모바일과 데스크탑 구조를 모두 의식하고 있다

---

## 8. 현재 디자인의 한계

리디자인을 고려해야 하는 이유도 분명하다.

### 8-1. 브랜드 톤이 조금 혼재되어 있다

- 서비스 명은 `산책메이트`에 가깝게 읽히는데
- 실제 UI 내부 브랜드명은 `VillageMate`로 표현된다

즉, 서비스 이름과 시각적 브랜드 표현이 완전히 정리된 상태는 아니다.

### 8-2. 데스크탑 톤이 기능보다 더 고급스럽게 보일 수 있다

글래스모피즘과 배경 연출이 강해서,
실제 서비스의 본질인 `동네 기반 실용 매칭`보다
조금 더 쇼케이스형 UI처럼 보일 여지가 있다.

### 8-3. 피드 / 마이페이지는 아직 차별적인 성격이 약하다

기능은 나뉘어 있지만,
새 프로젝트에서는 더 명확하게

- 피드는 `동네 산책 커뮤니티`
- 마이페이지는 `신뢰와 활동 관리`

로 톤을 분리할 수 있다.

### 8-4. 리디자인 여지가 충분하다

현재는 “따뜻한 반려견 앱” 방향이 강하다.
하지만 같은 서비스 주제로도

- 더 로컬 서비스답게
- 더 미니멀하게
- 더 프리미엄하게
- 더 커뮤니티 친화적으로

다른 디자인 해석이 가능하다.

## 9. 새 디렉토리에서 유지해야 할 것

새로운 디자인으로 다시 만들어도 아래는 유지해야 한다.

### 서비스 본질

- 동네 기반 산책 메이트 탐색
- 실제 산책 연결
- 신뢰 정보 중심 UX

### 핵심 화면 구조

- 로그인 / 회원가입
- 지도
- 피드
- 채팅 목록
- 채팅방
- 마이페이지

### 핵심 정보 구조

- 강아지 정보
- 사용자 신뢰 정보
- 거리 / 최근 활동
- 산책 스타일 / 선호 시간
- 산책 요청 -> 채팅 연결 흐름

### 제품 성격

- 실용적
- 따뜻함
- 신뢰 중심
- 동네 생활형 서비스

## 10. 새 디렉토리에서 자유롭게 바꿔도 되는 것

같은 메인 테마를 유지하되 아래는 새롭게 바꿔도 된다.

### 비주얼 아이덴티티

- 컬러 시스템
- 타이포 스타일
- 카드 형태
- 레이아웃 밀도
- 배경 연출
- 아이콘 톤

### 브랜드 표현

- 서비스명 표기 방식
- 로고 스타일
- 헤더 구조
- 소개 카피 톤

### 레이아웃 방식

- 데스크탑 셸 구조
- 지도와 리스트의 배치 방식
- 피드 위젯 구조
- 마이페이지 정보 배치
- 채팅 상단 정보 구조

### 감성 방향

- 더 미니멀한 방향
- 더 도시적인 방향
- 더 프리미엄한 방향
- 더 로컬 커뮤니티다운 방향

단, 바꾸더라도 `산책 매칭 서비스`라는 본질이 흐려지면 안 된다.

## 11. 새 프로젝트를 위한 리디자인 목표

새 디렉토리에서 만드는 프론트는 아래를 목표로 하면 된다.

### 핵심 목표

- 같은 서비스 주제를 유지한다
- 현재 프로젝트보다 더 일관된 브랜드 톤을 만든다
- 웹에서도 더 자연스럽고 설득력 있는 구조를 만든다
- 포트폴리오로 보여줬을 때 “디자인을 새롭게 해석한 프로젝트”로 보이게 한다

### 세부 목표

- Map을 더 강력한 대표 화면으로 만든다
- 신뢰 정보의 시각적 계층을 더 명확히 만든다
- 피드와 마이페이지 성격을 더 분명히 나눈다
- 데스크탑에서 모바일 확대판이 아니라 웹다운 구조를 만든다

---

## 12. 추천 리디자인 방향

같은 테마를 유지하면서도 아래 중 하나로 해석할 수 있다.

### 방향 A. 로컬 라이프스타일형

특징:

- 동네 생활 서비스 느낌 강화
- 편안하고 따뜻한 컬러
- 커뮤니티 감성 강화
- 실용성과 친근함 균형

어울리는 경우:

- 가장 안전하고 설득력 있는 포트폴리오를 원할 때

### 방향 B. 미니멀 신뢰형

특징:

- 장식을 줄이고 정보 중심
- 매너온도, 거리, 최근 활동을 더 선명하게 강조
- 도시형 서비스처럼 정제된 레이아웃

어울리는 경우:

- 더 성숙하고 제품다운 인상을 주고 싶을 때

### 방향 C. 프리미엄 컴패니언형

특징:

- 고급스러운 톤
- 좀 더 감성적인 사진 / 비주얼 활용
- 프리미엄 반려견 라이프스타일 서비스 느낌

어울리는 경우:

- 시각 완성도를 강하게 보여주고 싶을 때

## 13. 새 프론트에서 반드시 충족해야 할 UX

새 디자인으로 바뀌더라도 아래는 꼭 살아 있어야 한다.

### 사용자가 3초 안에 알아야 할 것

Map:

- 근처에 누가 있는지
- 어떤 사람이 나와 잘 맞는지
- 요청 가능한지

Feed:

- 실제 활동이 있는 서비스인지
- 동네 분위기가 어떤지

Chat:

- 누구와 무슨 맥락으로 대화 중인지
- 다음 행동이 무엇인지

MyPage:

- 내 신뢰도와 활동 수준이 어떤지

## 14. 기술 스택 참고

현재 프론트 작업물 기준 기술 스택은 아래다.

- React 19.2.3

- Tailwind CSS v4

새 디렉토리에서도 같은 스택을 유지하면,
기존 구조를 참고하면서도 디자인만 새롭게 해석하기 좋다.

## 15. 새 프로젝트 작업 권장 순서

1. 현재 서비스 본질을 유지할 핵심 정보 구조를 확정한다
2. 새 브랜드 톤과 비주얼 방향을 정한다
3. Map 화면부터 새롭게 설계한다
4. Chat, Feed, MyPage를 그 톤에 맞게 확장한다
5. 마지막에 Auth와 공통 컴포넌트를 정리한다
6. 모바일과 데스크탑을 각각 따로 검토한다

## 16. 최종 정리

현재 디렉토리의 프론트는 `강아지 산책 메이트를 찾고 실제 산책 약속까지 이어주는 동네 기반 매칭 서비스`로 정리할 수 있다.

새 디렉토리에서 다시 만들 때는 이 서비스의 본질은 유지하되,

- 브랜드 표현
- 레이아웃
- 비주얼 테마
- 정보 계층

을 새롭게 재해석하면 된다.

즉, 새 프로젝트의 목표는

`같은 서비스 주제를 가진 다른 디자인의 웹 포트폴리오 프론트`를 만드는 것이다.
